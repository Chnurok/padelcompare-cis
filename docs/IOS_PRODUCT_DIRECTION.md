# iOS Product Direction

## Position

PadelCompare should be built as an iPhone-first decision product, with web acting as acquisition, trust, and partner surface.

Not the other way around.

## What web is for

- SEO landings
- model pages
- partner / affiliate / B2B proof
- lead capture
- public trust layer for the brand

## What the app should own

- saved shortlist
- saved compare sets
- onboarding quiz
- alerts on price drops / restocks
- richer player profile
- push notifications
- premium subscription

## Competitive angle

To be competitive, the app cannot just be a catalog in native chrome.

It should win on:

1. faster decision flow than generic stores
2. better shortlist quality than broad review sites
3. saved state and re-engagement
4. identity: “this app helps me choose my next racket”

## Recommended build order

1. Launch domain-backed web product.
2. Keep improving catalog, compare, finder, and lead capture.
3. Fork a dedicated Expo iOS app using the same API/data model.
4. Ship v1 native flow:
   - onboarding
   - shortlist
   - compare
   - save
   - offer out
5. Add subscription / alerts only after the core loop feels strong.

## Naming implication

The domain and app name should feel like a product, not a content site.

That favors:

- `PadelCompare`
- `PadelCompare.io`
- `PadelCompare App`
